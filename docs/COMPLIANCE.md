# 店主合规与责任手册

> 这份文档只写给**店主**：自己在自己的机器上跑一个开店节点、自己上架商品、自己收款发货、自己承担法律责任的人。
> 读完之后你应该清楚三件事：**你该做什么、别指望什么、被投诉或被调取数据时怎么办。**
> 买家在聚合前端 `fedmall.bityuan.com` 浏览下单；你的店就是那个列表里的一个独立站点。
>
> **本文不是法律意见，也不能当法律意见用。** 正式经营前请咨询执业律师。

## 1. 三句话结论

1. **这里没有"平台"。** 商品、订单、客户资料全部留在你自己的机器上；没有中央服务器、没有账号体系、没有客服中心。传统电商里"平台"承担的那部分审核、客服、赔付、代扣代缴，在这里**没有落到任何人头上，而是完整地落回你**。
2. **KYC / 实名 / 反洗钱筛查没有实现，而且不是"还没做"。** 货款在链上托管合约里，合约里**没有任何**管理动作能冻结、划扣或没收它——就算你想配合一个"冻住这笔钱"的要求，你手上也没有这个权力。
3. **加一张实名表单不会让你合规，只会制造"看起来做了"的假象。** 谁开店、谁上架、谁收款、谁发货，谁就是这一单的经营者；这份义务不会因为软件没做而消失。

## 2. 为什么这里没有"平台"，这对你意味着什么

| 维度 | 传统电商 | 你这里 |
|---|---|---|
| 平台角色 | 平台审核商家、扣款、客服、仲裁、兜底 | **没有平台**：没有客服热线、没有平台垫付、没有平台仲裁 |
| 支付 | 第三方支付，秒到、可退款 | 链上交易：要钱包签名、要等区块确认、**不可撤回**、要付 gas；买家可能在钱包里拒绝签名 |
| 数据 | 一个中心数据库，全站可搜索、可排序 | 数据分散在各店自己的机器上；**没有全站商品总数、没有全站排序、没有总页数** |
| 店铺 | 平台上的一个卖家账号 | **一个独立的站点**：可能离线、可能被治理停用，离线时它的商品就不出现 |

- **好的一面**：没有人能审核你、没有人能单方面下架你、没有人能拿走你的客户名单——数据只在你自己手里。
- **代价一**：出了事**没有人替你处理**。别人读不到、改不了、删不掉你的数据；相应地，**也没有人替你删、替你答、替你赔**。你不回应，就是一单没有回应。
- **代价二**：**门口没有保安**。任何人在任何地方跑起一个节点就能开店、就能上架任何东西；没有平台审核、没有类目准入、没有商品报备、没有禁售关键词库。**"别人也在卖"不是你的合法依据，"软件放行"也不是。**

## 3. 你承担的是商户义务（经营者责任）

- 你＝**这一单的卖方 / 经营者**：跑节点的人、上架商品的人、收钱的人、发货的人。没有人替你审核商品、答客服、兜底、申报。
- **一条必须记住的判据：软件的边界是技术边界，不是法律边界。** 软件接受了一单，不代表这一单在你所在的辖区是合法的。
- **CNY 标价 + 加密资产结算**：界面上商品以人民币标价，实际结算用加密资产（托管合约只接受原生 BTY，没有法币通道、没有币种配置）。这个组合本身就落在**需要专业判断的区间**里。
  - 它与你"有没有做实名"是**两件独立的事**：以人民币标价、以加密资产结算的经营行为，不会因为加了一张实名表单就变成另一种行为；反过来，没加表单也不自动等于违法。**"做了实名就合法 / 不做就违法"这个二分是错的**，而这正是"加个表单求安心"最容易掉进去的坑。
  - ⚠️ 上面写的是"这需要专业判断"，**不是**"这违法"或"这合法"。请带上你的**商品类目、主体形态、所在地、结算方式**去问执业律师，本文刻意不替你下这个判断。
- **不要指望这些**（都不是"配置没打开"，是按这个架构不会有）：KYC / 实名 / 身份核验；反洗钱、制裁名单筛查、交易监控、可疑交易报告；税务计算、发票开具、代扣代缴、税务申报；年龄验证；商品合规判定、禁售类目审核、关键词过滤；资金冻结 / 划扣 / 没收；平台客服 / 平台垫付 / 平台仲裁；消费者法上的救济通道。

## 4. 你的节点存了什么、什么会被擦、什么刻意保留

你节点里的数据库是**订单履约的唯一记录**：没有第二份，也没有上游副本。所以"什么能删、什么不能删"必须由你自己清楚。

| 会被擦除的个人信息 | 处理方式 |
|---|---|
| 收货信息（收货人姓名 / 电话 / 地址） | 置为空白 |
| 买家订单备注、发票抬头与纳税人识别号 | 置为空白（"这单要不要开票"这个处理状态不是个人信息，保留） |
| 售后 / 争议陈述**正文** | 正文置为墓碑串，**行不删**：谁在什么时候提交过陈述是资金争议的事实记录 |
| 证据附件 | 数据库记录与磁盘文件**一并删除**（只删记录不删文件等于"数据还在磁盘上"） |

| 两条擦除通道（都只有店主本人权限，店员不行） | 怎么触发 | 说明 |
|---|---|---|
| 显式删除请求 | 对某一张订单调用节点的「删除个人信息」接口 | 立即擦除该**终局**订单的个人信息；重复调用不会有第二次变更（幂等） |
| 保留期到期自动擦除 | 保留天数配置项 `MK_PII_RETENTION_DAYS`（**默认 180 天**）；也可手动让它跑一轮 | 资金流已终结的订单静置超过 N 天后自动擦除 |

保留期要点（**写错值只会让擦除继续跑，不会让它停**）：
- 关闭自动擦除的判据是"**取整后等于 0**"，不是"必须写成字面量 `0`"：`0.5` / `00` / `+0` / `-0` 同样会关闭；反过来，**缺失 / 空串 / 非数字 / 负数一律回退到 180 天、而且是开着的**——把 `-1` 当成"关闭"会让擦除照常运行。
- 周期扫描**启动即跑一轮**，之后每 **6 小时**一轮；单轮有数量上限，超出时会标注"被截断"，再跑一次即可继续。擦除动作本身也会刷新订单的更新时间。
- 擦除状态只在节点的健康检查输出里能看到（没有单独的查询接口）：**静默失败就等于个人信息一直留着而无人知晓**，请定期看一眼。删附件时若磁盘删除失败会留告警并在下次重试——**收到这类告警请人工确认磁盘**，不要假定已经清干净。
- 擦除会写审计（**只记计数、不含被擦掉的内容**）；**不要手工跑 SQL 改库**——手工改库不会清理附件文件，也不会留下审计记录。为什么只有店主能删：删除不可逆，且它同时抹掉卖家侧履约所需的信息（收货信息一旦擦除，该单此后只能按链上记录处理）；店员能做发货、退款，但不应该一个人把证据清空。

**在途订单不能擦**：`草稿 / 已托管 / 已发货 / 争议中` 的订单一律拒绝擦除——你还要靠收货信息发货、处理售后，退款时也得能联系买家。"买家下单后立刻要求删除"只能等订单走到终局。可擦的终局状态：`已确认收货 / 已结算 / 已退款 / 已超时释放`，外加从未上链托管的弃单。

| 刻意保留的内容 | 为什么保留 |
|---|---|
| 金额、订单状态、链上托管单号、支付交易哈希、链上事件史（事件名 / 块号 / 交易哈希） | **账目与链上凭证**：删掉就等于篡改账本；链上那份公开历史本来也删不掉，而它是争议与对账的唯一依据 |
| 平台费 / 净额 / 结算口径相关字段 | 同上（税务与对账仍须线下人工处理） |
| 物流单号、退货地址与退货备注 | "这单确实发过货"的证据；售后事实记录 |
| 已交付的兑换码 / NFT 编号 | 交付事实："这个东西已经给他了"；删掉会让"是否已交付"无据可查 |
| 评价正文（不含个人信息的部分） | 公开的参考信号，属于交易事实 |

> **一句话记住**：**"删除个人信息"不等于"这一单从系统里消失"。** 擦的是个人信息，留的是交易与资金事实。这个口径必须对买家讲明（写进你的店铺公告）。

个人信息处理要点：**收货信息（姓名 / 电话 / 地址）与开票抬头、税号属于个人信息**，你要自己想清楚为什么收集、留多久、怎么删、谁能看；**你只能导出你自己节点里有的东西**，你不掌握的数据既拿不到、也不该声称有；**买家目前没有自助的删除 / 导出入口**，他只能联系你，你无响应时他无路可走——**"收到删除请求要回"是你自己的义务，不是软件的功能**。

## 5. 你手里实际有的合规抓手（以及每个抓手的边界）

下面每一条都是**机制**，不是**政策**：机制＝软件提供一个可用的动作和一条可核验的记录；政策＝软件替你判断这件事合不合法——**后者一概不做**。

**① 年龄限制商品：声明 + 留痕 + 一条拒绝下单的理由（不是年龄验证）**

| 环节 | 实际行为 |
|---|---|
| 声明 | 商品级开关「年龄限制」，在卖家面板的商品表单里勾选 |
| 锁定 | 该声明随商品内容一起算进商品快照哈希；下单时订单锁定这个哈希，买家可本地复算核验"下单那一刻这件商品有没有声明限制" |
| 买家确认 + 留痕 | 建单必须带显式的确认断言；**声明了限制而没带断言 → 直接拒单**（是否受限取决于商品本身，不是客户端说了算）。订单上记录这次确认，非限制商品一律记为"无"，避免留下误导性痕迹 |

边界（必须讲清，否则你会高估它）：**它不是年龄验证**，只是"买家在页面上点过确认"的留痕，**不构成年龄证明，也不构成任何资格结论**；它挡的是"没声明也没提示"，挡不住"明知故买"；系统里与年龄有关的全部东西就三样——商品上的一个开关、建单请求里的一个客户端断言、订单上的一个留痕，**没有**证件上传、**没有**出生日期字段、**没有**任何第三方核验。真要做年龄核验，那是你自己的线下流程，不是这个软件能提供的保证。

**② 下单风控闸：你想在店门口拦一单，只有这一个官方接入点**

形状是：**你自己配一个网址，节点在建单前问一句你自己的服务**——你的服务说放行就照常建单，说不行就不建单。

| 配置项 | 默认 | 作用 |
|---|---|---|
| `MK_ORDER_GATE_URL` | 空（**关闭**） | 风控服务地址。非空即等于"本店已开启风控"；必须是可解析的 `http` / `https` 地址，否则视为未开启 |
| `MK_ORDER_GATE_SECRET` | 空（不签名） | 选填签名密钥；配置后请求带签名头，你的服务只需实现一个校验器 |
| `MK_ORDER_GATE_TIMEOUT_MS` | `3000` | 单次请求超时（毫秒）；超时按"不可达"处理 → 拒单 |

- **它只存在于你和你的服务之间**：节点不内置风控服务、不下发策略、不参与判定。你把什么规则（实名、地域、限购、黑名单、内部风险规则）放进那个网址，是**你的决定与你的责任**——它是**你的**策略执行点，**不是**这个项目的合规能力（项目不提供风控服务、不提供策略模板、也不判断你的策略是否合法）。
- **数据最小化（重要）**：请求里**只发交易要素**（买卖双方地址、商品、规格、数量、金额、时间）；收货人姓名 / 电话 / 地址、买家备注、发票抬头与税号**永不进入请求体**。**风控服务不该变成个人信息外流通道**——你若把它接到第三方，请自己评估那个第三方。
- **fail-closed**：只有你的服务明确回答"放行"才建单；返回别的形态、重定向、5xx、超时、不可达，**一律拒单**。风控最需要生效的时刻（服务异常、被攻击、网络抖动）恰恰是它最容易挂的时刻，静默放行等于没开。
- **代价与逃生**：你的风控服务一挂，**全店下不了单**；逃生通道就是把这个配置清空。**拒单没有副作用**：闸门在本地校验之后、写库之前，所以既不插订单行、也不占库存；买家看到的报错写着"**本店**风控未放行"，不是平台或链上的拒绝。另外注意分工：闸门管"**这一单卖不卖**"，"**谁在访问**"要在更前面那一层解决——那一层拦得更早，请求根本到不了节点，**所以它的留存与留痕都要你自己实现，节点侧什么都不会留下**。

**③ 违禁 / 非法商品：政策由你自己写**
- **没有任何中央审核**：没有平台审核、没有类目准入、没有禁售关键词库、没有商品报备——任何人在任何地方部署一个节点就能上架任何东西。
- **所以违禁品政策必须由你自己写**，并写进**店铺公告**（公告存在你自己的节点里，改完即生效）；你对自家店的公告、商品描述、评价回复内容负责。别把"别人家也在卖""软件没拦我""链上没人管"当免责理由——可执行的顺序是：上架前自己判断 → 公告里写明禁售清单与售后政策 → 用下单风控闸把判断不了的单挡在门外 → 出事时按第 6 节处理。

**④ 内容哈希存证：事后不可否认，不是事前拦截**
- 评价与争议证据的**内容哈希**可以上链存证，提供"存在性 + 时间戳（存的是块号）"证明：你事后删改自己数据库里的内容，当事人 / 仲裁人仍可凭原文哈希主张"该内容在某块之前确实存在"。**只存哈希**：正文（评价、证据、兑换码、地址）**永不上链**。
- ⚠️ **它证明的是"存在与时间"，不是"作者是谁"**：存证先到先得，任何人都能替一个哈希存证，链上记录的"最先提交者"**不是**"谁写了这段内容"——**不要**用它做任何身份判断。
- 存证入口由买家一侧决定，**你关不掉买家的存证**；存证可选，并且由买家自己付 gas。
- 每笔订单还会保留**链上事件记录**（事件名、块号、交易哈希），用于逐单对账与争议举证。两个如实说明：事件史**有上限**（超出丢弃最旧的），**完整历史以链上为准**；手动同步补出的镜像事件没有独立的交易哈希。**这两项是"事后不可否认"，不是"事前拦截"**：它们不判断内容是否合法，也不判断交易是否合规。

## 6. 收到买家投诉时的处理步骤

> 总则：**没有任何一方能替另一方做合规动作**。数据在你自己的机器上——别人读不到、改不了、删不掉；相应地，**别人也替你清不掉**。下面的动作必须由你自己执行。

**第 0 步 · 先停下来（最直接、最有效的一步）**：关店 / 注销登记（把本店移出活跃店铺目录，聚合前端不再展示）→ 把商品逐个下架（立即止血）→ 停掉节点进程（最彻底：接口不可达，前端降级为"离线店铺"）。
**注意：以上动作都不会退回任何资金**，也不会改变在途订单的链上状态。**停业是"不再卖"，不是"清账"。**

**第 1 步 · 保全并导出你需要的那部分记录**：前提是**你只能导出你自己节点数据库里有的东西**（全部仅店主可调，每次导出都会写一条审计记录）。按需导出：**订单全量**（含收货信息、金额 / 已退额 / 平台费 / 净额、链上托管单号、支付哈希、物流单号——金额三列自洽：净额 = 金额 − 已退 − 平台费，可在表格软件里手算复核）、**收款流水**（对账用，入账口径＝已入账状态）、**商品清单**、**码池**（含兑换码原文，敏感，仅店主可导）、**管理审计**。

用这份审计时要知道它的边界（否则会高估它）：
- 它**只记管理侧动作**（上架、改价、发货、批量发货、发码 / 发 NFT、取消、同步、评价回复、退货处理、店铺设置、店员增删、通知配置，以及**全部导出与个人信息擦除**）；**买家动作不进审计**——买家的资金行为由链上事件史与证据覆盖。所以"审计里没有这条"**不等于**"这件事没发生过"。
- 审计**按设计不含**兑换码原文、完整收货地址与令牌；擦除相关记录**只记计数**，不会把擦掉的内容再抄一份。写入失败只告警、不影响业务动作，**所以审计不是强一致账本——真要举证，链上那份才是权威**。
- **关于"给我的订单数据"的直接回答**：上面那份订单全量就是节点持有的**全部**订单相关记录，**没有第二份、也没有上游副本**。链上那份（托管单、事件、支付）是公开的，任何人都能读到，不需要你来提供。

**第 2 步 · 如实回应你能证明的部分**：**给得出的**——订单记录、审计记录、链上单号与交易哈希（这些可核验）；**给不出也不该编的**——你不掌握的身份信息、你没做过的核验结论，**不要**用"我们做了实名 / 风控"去回应，如果事实上没有，那就是在制造虚假陈述；**要说清留存边界**——个人信息可以按第 4 节擦除（默认 180 天保留期），但**账目与链上凭证不擦**，链上那份**任何人都删不掉**。

## 7. 收到监管 / 司法合法调取请求时的处理步骤

先分清对方要的是什么，因为它直接决定你能不能给：

| 对方要的 | 你有没有 | 怎么给 |
|---|---|---|
| 订单与收货信息、开票信息 | **有**（在你节点里） | 按第 6 节第 1 步，按时间 / 状态导出后交付**你核验过**的那一份 |

**"把这笔钱冻结 / 退回"这类要求，你要如实说明四件事：**
1. 货款**不在你手里**，在链上托管合约里。你能做的只有"**拒绝交付**"——不发货、不交付、不点确认。

3. 合约里**没有**暂停、冻结、划扣、没收这类能力，**没有**任何函数能指定一个收款地址打钱。**你想配合也没有这个权力**——这不是推脱，是这套架构的事实。
4. 你能做的是：**不继续卖**（第 6 节第 0 步）＋ **如实提供你有的记录** ＋ **说明你做不到的部分**。

**建议顺序**：① 先停（关店 / 下架 / 停进程），避免继续产生新交易；② 核验请求方与请求范围（谁提出、依据什么、要哪些字段、期限多久）；③ **只导出请求范围内的数据**并留下导出审计；④ 如实回应，包括"哪些我没有、哪些我做不到"——**不要**用你没做过的核验来搪塞；⑤ 涉及个人信息删除的，走正式擦除通道，不要手工改库；⑥ 把整个过程记下来：导出了什么、给了谁、什么时候。

## 8. 买家侧的保护机制：可以当卖点，但边界要一起讲

一个匿名的对手方**无法援引消费者法上的救济**（他没法起诉一个叫不出名字的人，也没有平台可以投诉）。所以这套系统把"保护"做成了**结构**而不是**权利**。诚实地说：**这些是替代品，不是等价物。**

| 机制 | 它实际做到什么 | 边界 / 对你的代价 |
|---|---|---|
| **链上托管 + 按金额拆分结算** | 钱先锁在合约里，确认收货 / 仲裁裁决 / 超时才结算；少发、部分损坏、运费分摊都能用"按金额拆分"表达（谈得拢走"买家授权 + 你执行"，谈不拢交仲裁人裁决）。买家一申请退款，**超时释放就被禁**，你无法抢跑收款 | 结算由链上状态机决定；**你同意退款只能退"全额"或"买家已精确授权的那个金额"**，不能单方面指定一个较小的金额把订单结掉；退款申请期间你的货款会冻结到退款或争议有结果为止 |
| **你自愿质押的保证金 + 仲裁罚没** | 出纠纷时，订单链上终局后**只有仲裁人**能发起罚没来补偿买家，钱**直达买家**、不经中间账户 | **罚没不是保险**：未质押就无钱可罚；单笔有比例上限、跨单有速率上限；窗口期间你已到期的撤资会被锁住（默认最多一个窗口，约 30 天） |
| **履约画像（公开统计）** | 托管单量 / 买家确认率 / 争议率 / 发货中位耗时，口径是链上事件，第三方可独立扫链重算并戳穿虚报 | 发货耗时是节点本地自述；争议样本过少时比率不展示 |
| **买家本地黑名单** | 买家可拉黑你的店铺地址或网址，该店不再出现在首页与列表，下单与重新支付被硬拦 | 纯本地、不同步、不上链；**你看不到、也无法申诉** |
| **争议中的撤诉出口** | 争议状态下买家可主动确认收货、结束订单 | 撤诉会**同时放弃对你的罚没资格**——所以"结束订单"与"保留追索"在仲裁人失能时是二选一 |
| **自动放款倒计时** | 订单详情显示"还剩多久自动放款"，买家知道最迟何时必须行动 | 超时是**逐单参数**（下单时写入、上链冻结），生产默认约 7 天 |

**这些机制替代不了什么**（别把它们当成你拥有的能力）：没有客服、没有平台垫付、没有平台仲裁；没有**买家保证金 / 买家信誉**——恶意买家反复下单、拒收、滥诉**没有经济成本**；没有**争议时限 / 仲裁人补偿 / 上诉通道**——争议一旦进入就**没有任何时限**，仲裁人不管事时资金**无限期冻结**（你自己丢私钥同理）；**罚没不是保险**——未质押的店主跑路，买家仍然得不到任何补偿。

这份清单对你是双面的：**它是买家敢不敢在你店里下单的理由，也是你必须自己守住的底线。**
