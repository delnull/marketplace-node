# 联邦商城 · 开店节点：钱、订单与边界

> 这份文档只讲三件事：**钱是怎么被保护的、订单怎么流转、这个产品刻意不做什么**。
> 读者是店主与买家——懂一点区块链常识（钱包签名、gas、区块确认）就够，不需要读得懂合约代码。
> 立场一句话：**没有平台，但依然可信**。可信来自链上托管、公开可查的链上事实与保证金，
> 而不是客服、审核与平台垫付。凡是我们做不到的，下面都会直说。

## 一句话看懂：链上管什么、链下管什么

每家店 = 店主自己服务器上的一个节点。商品、订单、客户资料留在店主自己机器上；链上只有目录与资金。

| 层 | 管什么 | 意味着什么 |
|---|---|---|
| 链上（BTY EVM 主网，chainId 2999） | 店铺目录（谁在卖、托管合约是哪个）、货款托管、评价与证据的**内容哈希**存证、卖家保证金 | 钱与目录在链上：改不了、删不掉、谁都能公开核验 |
| 链下（店主自己的节点） | 商品、订单、售后与争议记录、物流单号、交付的码与凭证、客户资料 | 数据分散在各家店自己手里，没有中心库；店离线就看不到 |

- 买家在聚合前端 https://fedmall.bityuan.com 选商品，**货款锁进链上托管合约**：下单即托管，店主不能直接拿走。
- **没有平台**：没有客服热线、没有平台账号体系、没有平台垫付、没有中心数据库。因此**没有全站商品总数、没有全站排序、没有总页数**——聚合是在浏览器里把各店数据合并出来的，某家店离线时它的商品就不出现。
- 支付是链上交易：要钱包签名、要等区块确认、**不可撤回**、要付 gas，买家也可能在钱包里拒绝签名。全链路只收原生 BTY，**CNY 只是标价单位**。

## 钱是怎么被保护的

**下单到托管**：买家选好商品 → 节点锁定商品快照、汇率、应付金额、超时区块数 → 买家钱包对 `Escrow.createOrder` 签名，把货款锁进合约 → 卖家发货/发码 → 买家确认收货（或超时）→ 合约结算给卖家（可扣平台费）。买家签名前会看到"钱付给哪个合约、什么条件下释放"。

下单弹窗还会核验两件事：要付款的托管地址**必须是合约**（不是普通钱包地址），且**与店主在链上登记的一致**；两者任一不符会直接禁止支付。付款后节点再按链上日志核验订单号、金额、卖家、买家四要素与本地锁定值**逐项一致**，不符不推进——防伪造托管与第三方代付。

**四条结算出口**（钱只能从这四条路走出去，没有第五条）：

| 出口 | 谁触发 | 触发条件 | 钱怎么走 |
|---|---|---|---|
| 买家确认收货 | 买家 `confirmReceipt` | 订单已托管；争议中同样可用（= 撤诉放款，自愿放弃追索） | 扣平台费后全额给卖家 |
| 卖家同意退款 | 卖家 `approveRefund` | 买家已申请退款，或争议中主动认赔 | **只能全额退买家**，或退**买家事先精确授权的那个金额**；不允许卖家自己填一个数 |
| 仲裁裁决 | 仲裁人 `arbitrate` | 订单已进入争议 | 全额退买家 / 全判卖家 / **按金额拆分**；拆分时买家拿退款、卖家拿余额，平台费只对卖家留下的部分计 |
| 超时释放 | 任何人都可调 `releaseExpired` | 超过约定区块数，买家既没确认收货、也没有待决的退款申请 | 全额给卖家（保护卖家不被无限拖单）。超时后、被释放前买家**仍可发起争议**——确认、争议、超时释放三者**先上链者生效** |

- **平台费只对"卖家实收部分"计**：`费 = （托管额 − 已退买家）× 费率`，全额退款给买家时恒不扣费。费率与收取方在**订单创建时快照锁定**，事后的费率调整不影响在途订单；收取方未配置时一律不扣费；默认费率是 0。
- **资金守恒**：每一单的托管金都在**同一笔交易内**一次结清（买家退款 + 平台费 + 卖家净额 = 托管额），不存在"退一半、另一半悬在合约里"的中间态。
- **收款方是多签/合约账户时**：钱不会自动打过去，而是记账在托管合约里、由该地址自己领取；订单本身照常结清（先保证订单能结，再谈费用到账）。
- **托管地址核验有边界**：登记层对托管合约做了"地址 + 合约代码哈希"的双重锚定，但**同一份代码的克隆实例**无法只靠页面信息识别，要判断它还需要链下信息。

## 订单状态流转

**链上是权威，节点只是本地副本。** 订单真正的状态由链上决定，节点把链上事件抄回自己的库里，界面读的是这份副本。

| 本地状态 | 含义 | 谁把它推到这一步 |
|---|---|---|
| `draft` | 本地草稿：参数已锁定，钱还没上链 | 买家下单（或店主代下） |
| `escrowed` | 货款已在链上托管 | 链上 `OrderCreated` 事件 / 买家提交支付凭证 |
| `shipped` | 卖家已发货、已发码、已转 NFT | 卖家发货，或卡密类商品自动交付 |
| `confirmed` | 买家确认收货，钱已结算给卖家 | 链上 `ReceiptConfirmed` |
| `disputed` | 争议中：资金冻结、超时释放暂停 | 链上 `DisputeRequested` |
| `refunded` | 终局：全额退回买家 | 链上 `RefundApproved` / `Arbitrated`（退款额 = 托管额） |
| `settled` | 终局：钱结算给卖家（判卖家、或拆分结算，或"链上已结算但原因未知"的兜底） | 同上（退款额 < 托管额，含 0） |
| `expired` | 终局：超时释放给卖家 | 链上 `OrderExpiredReleased` |
| `cancelled` | 草稿在有效期内未支付，被本地关闭 | 超时自动关闭 / 买家或店主手动取消 |

- **回写有约 1 分钟的滞后**：节点只处理「链头 − 确认深度」（默认 12 块，BTY 约 5 秒/块，可调、设 0 = 关闭）之前的事件。好处是**短重组不会污染本地状态**，代价是刚付完款订单页要等一小会儿才变「已托管」。
- **`settled` 是"原因未知"的兜底态**：界面文案只说"钱已结算给商家"，不断言原因（可能是仲裁判卖家、可能是拆分结算、也可能是节点补账）——想知道是哪一种，看订单详情里的链上事件时间线。
- **售后标记与主状态并行**：买家链上申请退款后进入"退款待决"（冻结，期间禁止超时释放）；卖家拒绝后进入"已拒绝"，此时买家才获得发起争议的资格，且**不能再次申请退款**（防"申请→拒绝→再申请"把已超时订单的释放无限期冻住）。
- **已取消的草稿可能"活过来"**：如果链上托管后来真的落定了，节点会自动把它恢复为已托管，不需要人工干预。
- 卡密类商品在托管落定后会自动发码并进入已发货；实物需要物流单号，NFT 需要卖家先链上转账并登记 tokenId，节点核验链上转账后才算交付。

## 售后与争议怎么走

1. **买家申请退款**（`requestRefund`，只有买家能发）：订单冻结，**期间超时释放被禁止**（防卖家抢跑收款）。
2. **卖家回应**（`approveRefund` / `rejectRefund`，只有卖家能发）：同意就只能走"全额退"或"退买家已授权的那个金额"；拒绝则解锁争议资格。
3. **买家可以授权一个具体金额**（`acceptPartialRefund`）：把"我接受商家按这个数退"记到链上，卖家随后才能按这个数执行。它**不动钱、不冻结订单**。授权是**双向**的——授权 0 就是撤回；而且**买家一旦发起争议，之前那次授权会自动撤回**（把裁决权交给仲裁人之后，就不该再让卖家按旧价钱抢跑终结订单）；争议中若仍接受该金额，可以重新授权一次。
4. **为什么卖家不能自己填退款额**：终局状态由退款额决定，卖家若能单方面指定一个很小的数就"结算"了订单，买家之后既不能确认收货、也不能申请退款、也不能发起争议——链上没有任何回头的路。所以卖家手里的金额只有两个：全额，或买家点过头的那个数。
5. **发起争议**（`requestDispute`，只有买家能发）：前提是"已超时"或"退款申请已被卖家拒绝"。进入争议后资金冻结、超时释放暂停，双方各自提交陈述与证据附件（按阶段×身份校验，形成同一条时间线；附件限 png/jpeg/webp/pdf，单文件 ≤2MB、单条 ≤6 个、单订单 ≤20MB，下载一律经身份校验）。
6. **仲裁裁决**：全额退买家 / 全判卖家 / 按金额拆分（各让一步）。仲裁人的金额不需要当事人授权——中立第三方裁定本就不需要。裁决即链上终局。
7. **已交付商品的退款 = 线下追回协调**：码或 NFT 已经发给买家后，退款走链上，但库存额度要等卖家"确认收到退货"或"放弃追索"才回来；**码与 tokenId 不回池复用**（买家可能已经用掉了，安全第一；要再售必须重新导入），已交付过的码会作为"永不复用"的墓碑保留。

**卖家保证金（质押）与罚没**：店主可以自愿在链上质押一笔钱，出事时用来补偿买家。罚没**只有仲裁人能发起**，且只能按链上终局事实执行：

- **资格门槛**：只有当"钱是在**买家没有认可**的情况下判给卖家的"才可罚没。买家确认收货过（含争议中撤诉放款）的订单**一律不可再罚**；全额退款时卖家留下的部分是 0，也不产生罚没（同一个损失不能既退款又罚没）。
- **单笔上限** ≤ min（在池质押, （托管额 − 已退买家）× 罚没比例上限），且每单只能罚一次。
- **跨单有速率闸**：同一个店主在一个窗口（默认 30 天，治理可调、硬上限 180 天）内累计被罚 ≤ **开窗时**质押池的 50%（默认）；**窗口期间禁止提取已到期的质押**——否则卖家在第一个窗口被罚掉一半后把剩下的提走，后面的受害者就无钱可罚。
- **这是"有速率上限的单点信任"**：出金闸由仲裁人的动作触发，所以一把被盗的仲裁人密钥可以用近乎零成本的方式（1 wei 的罚没）反复把某店主的出金窗口往后推。治理侧有两条互补的救援手段：轮换仲裁人（窗口归属"开窗时的那个仲裁人"，轮换即让在途窗口作废，精确且定向）与一个**全局**的实时开关（关掉立刻放人，但会把包括恶意店主在内的所有人一起放开）。
- **罚没不是保险**：未质押的店被罚没时无钱可罚，没有仲裁确认的场景也没有补偿。所以界面会把"已质押 N / 未质押 / 读取失败（未知）"三态分开显示——"未知"不等于"确无"。罚没也全凭仲裁人主动发起，没有自动触发。
- **治理只能摘牌，不能动钱**：治理动作（停用、永久关闭登记）只影响目录可见性与新交易，**不触碰托管资金、在途订单与仲裁结果**。所以"已停用"**不等于**"已追偿"。

**仲裁人是链上单点信任，它失能时双方都被冻住（如实说）**：

- **买家**有两条出口：在争议中"放弃争议"撤诉放款（等于自愿放弃追索），或继续停在争议里等（资金冻结、不退不放）。**撤诉放款会同时放弃对卖家质押的罚没资格**——"结束订单"与"保留追索"是二选一；界面必须在确认层把这一点写出来。
- **店主**同样被冻：货款锁在合约里，只能等仲裁裁决或买家动作；**全额认赔是卖家唯一的单方出口**。
- **没有争议时限、没有仲裁人报酬、没有二审或申诉通道**（单仲裁人模型）。仲裁人不管事时资金**无限期冻结**，没有"逾期自动判"的兜底。

## 运费 / 年龄限制商品 / 开发票

这三项都是**机制**，不是政策：软件只保证字段被如实记录与校验，**不替任何人做合规判断**。

| 项 | 机制保证什么 | 不做什么 |
|---|---|---|
| 运费 | 商品级固定运费（¥0–¥1000，0 = 包邮）；**只有实物商品可设**，数字/NFT 商品带非 0 运费会被**显式拒绝**（不是静默归零）；**按单收取一次**、不随件数翻倍：应付 = 单价 × 数量 + 运费；运费进商品快照、下单时锁定，之后改商品运费不影响在途单 | **不做按地区/重量/件数的运费模板**；也表达不了"满件包邮"这类促销（只能改价） |
| 年龄限制商品 | 商品上声明了限制的商品，下单**必须由买家显式确认**才能建单，否则拒单；限制状态进商品快照，买家复算哈希就能核验"下单那一刻这件商品是否声明了限制" | **不做年龄验证**：那个确认只是"买家点过确认"的留痕，不构成年龄证明；哪些商品属于限制商品、政策文本怎么写，全部由店主/运营方自行界定 |
| 开发票 | 只保证"买家填的开票抬头/税号被如实记录、并对当事人可见"；订单终局后可随个人信息删除一并清空（是否要开票的处理状态保留） | **不计算税额、不判断税率、不生成发票文件、不代扣代缴、不做任何合规判定**——对账与报销仍须线下人工处理 |

收货信息是**选填**的：实物可以没有地址就成交（线下自提/协商）；填了也只是履约参考，**不入快照、不影响资金锁定**。开票信息与收货信息适用同一可见范围（买家本人 / 店主 / 仲裁人可见，匿名与第三人恒不可见）。

## 评价与存证

- **只上哈希，正文永不上链**：评价与争议证据的存证提交的是内容哈希，正文、附件、地址与理由都留在链下。
- **哈希以买家本地复算为权威**，节点返回的同名字段只作对照——否则店主下发一个假哈希就能架空存证。
- **存证入口与店主配置无关，店主关不掉买家的存证**；存证合约没有主人、没有审核；存证是可选动作，且需要买家自己付 gas。
- **它证明"存在与时间"，不证明"作者是谁"**：存证先到先得，任何人都能替一个哈希上链。所以链上那个"最先提交 0x…"只能说明**谁最先把它写上链**，界面按这个口径标注——**不要**据此判断作者身份。作者身份由链下确定（评价/陈述写在各家店的库里，写入接口按身份门控且请求带签名），链上只补"没被事后删改"这一条。
- **评价**：只有成交终局（确认收货 / 判卖家 / 超时成交）的订单能评，仅买家本人、一单一评、不可修改、不支持追评；店主可回复一次；公开面只显示匿名短地址，**不下发评分分布**（三条评价画出的柱状图会给人"这看起来像统计"的错觉）；评价入口有时间窗（默认 30 天）。
- **评价是参考信号**：防不了自买自评（两个钱包互买），也不做平台审核与删除，与履约画像同权展示。
- **履约画像**：托管单量、确认率、超时率、争议率与判向取自链上事件，第三方扫链可以重算对账，节点虚报没有意义；而"发货耗时中位数、运营起点"是**节点自述**，仅供参考；争议样本少于 5 笔时比率置空，避免小样本误导。

## 这个产品**明确不做**什么

下面这些**不是"还没做"，是由架构决定根本不会有**：没有中心数据库、没有平台账号体系、没有平台裁判，所以每一项都缺一个前提条件。

| 能力 | 为什么不做 | 替代路径 |
|---|---|---|
| 平台级购物车、跨店合并结算 | 资金按店独立托管，没有平台实体能担保合并 | 单店一单一次托管（数量 1–99 件） |
| 平台级优惠券 / 满减 / 促销 | 没有平台运营实体 | 单店想打折：直接改价（价格快照锁定天然支持活动价） |
| KYC / 实名 / 法币出入金 / 反洗钱 / 制裁筛查 / 实名年龄验证 | **刻意不做，且不打算做**：没有发照主体、没有开户环节、没有中心账户，资金从买家钱包直达托管合约、再从合约直达卖家钱包，治理也碰不到托管资金——**没有任何一方具备"拦下这笔钱"的地位**，硬做只会变成一句对链上毫无约束、却把责任推给读它的人的口号 | 合规能力由店主/运营方自行外接（下单前的风控闸、第三方网关）；**运营方自己的法定义务不因软件不做而消失** |
| 统一物流追踪 | 联邦没有统一承运商 | 只有物流单号字符串，没有轨迹时间线；退货走"买家回填单号 → 卖家确认收到 / 放弃追索"四步，物流状态线下或自接 |
| 评价的平台审核 / 删除 | 没有平台裁判 | 靠"参考信号"定位 + 店主单次回复 + 哈希存证 |
| 平台代扣式的保证金 / 罚没 | 在仲裁治理（多仲裁人、轮换、激励）成熟之前，把罚没权做成平台动作的单点风险过高 | 只有简化形态：自愿质押 + **单仲裁人**按链上终局事实罚没补偿买家；**多仲裁人 / 轮换 / 激励仍不做** |
| 完整 SKU 变体、运费模板 | 小型联邦店场景低频 | 单规格 + 数量；运费只有每商品固定值；不做按地区/重量/件数的模板 |
| 多语言 i18n | 目标市场暂定中文 | 界面为静态文案，未来可行 |
| 平台通知 / 客服工单 | 节点自治 | 店主可配订单事件通知（发到店主自己的接收端）；买家侧**没有**服务端推送 |

按界面区域还有一批"根本不会有"的：**交易类**不做加购、跨店合并、优惠券、折扣、划线价、积分、会员；**商品类**不做类目导航、标签、品牌墙、规格以外的属性筛选、商品视频、商品问答、分享、举报、联系卖家、客服聊天；**店铺类**不做店铺 logo 上传、简介富文本、所在地与距离、同城、粉丝关注、店铺优惠活动、结构化客服联系方式（除公告文本外无字段）；**搜索类**没有全站搜索，也没有联想补全、热搜词、历史记录云同步；**订单类**不做买家的订单关键字搜索、催发货、站内消息、物流轨迹、快递公司字段、评价图片、追评、点赞、修改或删除评价、撤销退款申请、删除已提交的陈述；**账户类**没有全局账号体系、没有"一次登录全网通用"、不云同步收藏、不跨设备同步地址簿、没有设置页与默认收货地址（切换账户只能在钱包侧发起）。

判据只有一条：**任何需要"中心化存储"或"平台裁判"的能力，在这个架构里都没有立足点。** 确有类似需求时走替代路径：折扣 = 改价；跨店合并 = 分单；客服 = 店铺公告 + 店主自建的通知接收端；评价治理 = 店主单次回复 + 哈希存证。

## 按设计生效的边界行为（不是缺陷）

- **买家可以从任意设备找回订单**：用连接的钱包地址向各店铺查询订单并合并，是换设备、清缓存、丢本地凭证之后的找回路径。代价（**地址会被广播给每一家店**）在页面上常驻写明，并给了收窄手段："仅我选定的店铺"——没勾的店收不到本次查询，页面按"跳过"如实计数，**绝不显示成"没有订单"**。它**不能**恢复丢失的私钥。
- **买家侧提醒是本地浏览器通知**（可选开启）：没有 Service Worker、没有后台推送、没有后端，判断只在「我的订单」页拿到数据的那一刻发生——**页面没打开就不会提醒**；换设备后开关与去重表都是空的。
- **本地凭证库存在浏览器里**（按钱包地址隔离）：是买家订单凭证（链上单号、托管合约地址、支付哈希、交付码原文、已授权的部分退款额）的**明文本地副本**，用于"店铺节点下线"时自救（可离线导出/导入，并对链上直接执行动作）。它是**尽力而为的副本，不是权威**：可能与节点或链上最新状态有偏差，一切以链上为准；**码原文等敏感内容明文存储**——共享设备慎用，换设备要手动导出/导入。
- **买家订单可被公开读取**（收据可无登录核验）：这是"没有平台账号体系"下的既定取舍，风险由运营公告与可选的访问限流承担，不会改成强制登录。
- **店主自配的通知（webhook）一期不持久化**：内存队列 + 最多 2 次重试，进程重启不补发；接收方必须按事件 id 去重（重试可能重复投递）。
- **链上状态对账只修不回滚**：后台定期复查静止过久（超过 6 小时）的非终态单，把"链上已终局、本地还在途"修回来；本地已经停在终态的行绝不触碰。
- **汇率与时间窗口是节点本地数据**：下单锁价后汇率波动自行承担（链上以签名金额为准）；看板与趋势按节点本地时刻统计。
- **地址簿存在浏览器本地**：不跨设备同步，换设备需重建。
- **操作员（店员）可以读到码池/NFT 池的原文**（处理退款与对码需要），因此**只应授权可信人员**；财务面（流水、看板、导出、审计）仅店主。
- **个人信息可删除，但有明确范围与保留期**：终局订单的收货信息、备注、开票抬头与税号、陈述正文、证据附件可由店主立即擦除，或按保留期（默认 180 天，0 = 关闭）自动擦除；在途单一律拒绝擦除（履约必需）。**评价正文、物流单号、退货单地址与备注、已交付的码与 NFT tokenId、金额与链上凭证刻意不在擦除范围内**（它们是交易事实与账目，链上那份公开历史也删不掉）——所以"删除个人信息"不等于"这一单从系统里消失"。
- **注册门槛是可选治理参数，默认 0 = 无门槛开店**：上调后约束新注册、注销后重新激活，**以及店铺转让的受让方**（否则"用达标地址注册→立刻转让给零质押新地址"一步就能绕过）。门槛是**入网时刻的快照式经济信号，不是锁**：注册后撤资是自由的，它只提高一次性的作恶成本，不保证"作恶时有可罚之物"。

## 已知缺口（未实现的能力，别指望）

**这一节是"别指望它"清单**：下面每一条都是**现在没有的能力**，不是"配置没打开"，也不是"再等等就有"。**本节不承诺任何一条会在未来实现。**

- **没有税费计算，也没有税务/发票合规逻辑**：订单里只有运费与开票记账字段，不计算税额、不判断税率、不生成发票文件、不代扣代缴。后果：对账/报销用的税额与发票仍须线下人工处理。
- **买家侧没有服务端或后台推送**：店主有通知接收端，买家侧**没有** webhook、没有邮件/短信、没有 Web Push、也没有 Service Worker；已有的只是页面内的本地浏览器通知——**关掉页面就没有任何提醒**，跨设备也没有通道。
- **没有争议时限（SLA）、没有仲裁人报酬、没有上诉通道**：争议进入后没有任何时限，仲裁人不管事时资金无限期冻结（卖家丢钥同理），买家没有"逾期自动判"的兜底。
- **没有买家保证金 / 买家侧信誉**：保证金与履约画像**只针对卖家**。恶意买家反复下单→拒收/滥诉没有经济成本，卖家侧也看不到买家的历史。
- **没有 KYC / 反洗钱 / 违禁品处理**（年龄限制只有机制层）：不做身份认证、不做交易筛查、不做商品合规判定；CNY 只是标价单位，实际以加密币结算。合规责任完全落在店主自身。
- **买家私钥丢失仍然没有恢复途径**：钱包私钥即账户，没有找回、没有托管、没有社交恢复。订单可以跨设备找回，但**私钥本身丢了**，该地址的托管单、评价、地址簿仍然动不了；本地凭证库也只是每浏览器的尽力而为副本。
- **仲裁人或卖家私钥丢失 → 争议资金永久冻结**：争议里的钱只有该合约实例上记录的仲裁人或卖家能移动，而**合约不可升级、重新部署对旧合约的余额没有任何权限**，救不回来；买家唯一（且吃亏）的出口是自己撤诉放款给卖家。
- **合约不可升级**：没有代理/迁移模式，出现合约级缺陷时没有"热修"路径。
- **链上事件被隔离后需人工介入**：坏事件连续失败会被移入隔离清单并跳过（这是为了不让一个事件把扫描窗口永久钉死），但**没有自动重放、也没有管理界面**，只能靠健康检查里的计数发现问题、人工补回订单。后果：不看这些信息的人会晚很久才知道出过问题。
- **节点不自带基础设施告警通道**：健康状态字段（后台轮询、对账、保留期擦除的活性）都如实暴露了，但**投递靠店主自己接监控**——不接监控时，健康检查可能一直是绿的，而节点早已停止同步链上状态；保留期擦除静默失败更隐蔽，它是不可逆动作，失败等于个人信息一直留着而无人知晓。
- **深度重组只有一半兜底**：比确认深度更深的重组会留下两类残状态——"链上已终局、本地仍在途"由后台对账自动修回；**"本地已停在终态、链上已不存在该终局"没有任何自动兜底**，只能人工核对（把确认深度调大可以降低概率，代价是回写延迟同步变长）。
- **诱饵单仍能打断买家的支付（已限损，未根除）**：未付款草稿的订单号是公开的，攻击者可以用极小金额抢先占掉它，导致买家随后的真实支付失败——**没有资金损失，但只能作废草稿重新下单**。
- **数据删除是"店主执行"而不是"买家自助"**：擦除通道与保留期都已有，但**买家没有自助的删除/导出入口**（必须联系店主，店主不响应时买家无路可走），保留期只有一个全局天数、不能按数据类型或法域分别配置。
- **买家侧的 gas 解释与费率预估未做**：结算页只写「gas 由你支付」（gas 是链上手续费、由发起的买家自付、不被店铺收取、失败或取消签名也会消耗一部分）；**没有量级预估，也没有"钱包余额不足"的前置提示**——余额只够货款时，仍要到签名阶段才会失败。
- **登记地址的域名归属证明未做**：链上只约束登记地址的唯一性，不证明域名控制权，抢注他人域名可以被登记。
- **另有一批具体的"没做"**：卖家商品列表的关键字搜索、码池导入的撤销（导入前有预览，但导入是不可逆的追加）、批量交付与批量同意退款、逐单填写不同物流单号、店铺转让与关店的引导界面（链上转让已实现，目前只能在钱包里手工执行）、仲裁人的申请/轮换/激励与案件认领、治理提案与投票、节点详情页。

## 店主上线前该想清楚的几件事

- **仲裁人与合约所有者必须是两个不同的地址，私钥冷存**：同一把钥匙出事会同时失去仲裁与所有权，**争议资金将永久冻结**。合约不可升级，更换需要走两步转让（提名 + 由新所有者自己确认接收），且几个合约要各做一遍。
- **显式决定一次"注册门槛是不是 0"**：默认 0 是"人人可开店"的定位，但门槛是**买家第二层补偿的唯一前提**——未质押的店被罚没时无钱可罚。要设就一次设成"小额但非零"（够覆盖一次典型纠纷的罚没上限即可），并让保证金在店铺页如实显示在买家眼前。
- **质押是自愿的，但会被如实标注**：买家会看到「已质押 N / 未质押 / 读取失败（未知）」，而"未知"与"确无"是分开显示的。质押撤资有冷却期，争议/调查期间还可被冻结，被罚过一次之后已到期的撤资最多要再多等一个窗口（默认 30 天，硬上限 180 天）——**先确认这笔钱不急着用**。
- **合规责任在你自己**：软件不做身份认证、不做交易筛查、不计算税额、不生成发票、不做年龄验证、不提供消费者法上的救济。这些不是"配置没打开"，是按本架构不会有；要合规就得自己外接能力、自备文案。
- **数据在你自己手里，备份与保留期就是你的活**：保留期擦除是不可逆动作；节点停止同步链上状态时健康检查可能仍然是绿的，**要按字段接监控**，不能只看"服务还活着"。
- **买家侧没有推送通道**：买家长期不打开订单页时，"已发货 / 退款成立 / 托管即将到期"不会被推送到任何地方；你配的通知接收端只解决你自己这一侧。
- **丢钥即损失**：店主私钥丢失会同时让在途售后与质押动不了，链上没有找回路径。
- **店铺转让只转让经营权**：在途订单的链上售后仍绑定原店主地址。转让前要在"轻转让（原主保留旧钥配合链上售后）"与"完整交割（先清零在途单）"之间做决定。
- **别替买家假设"自动放款"**：链上没有自动执行的机器人，超时之后是**任何人**（包括你）都可以触发释放；界面的倒计时文案也据此不写"自动放款"，只提醒"托管即将释放"。
